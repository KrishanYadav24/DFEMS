# DFEMS — ORACLE DATABASE 26ai OBJECTS CATALOG & SPECIFICATION

> **System:** Digital Forensic Evidence Management System (DFEMS)  
> **Database:** Oracle AI Database 26ai Free  
> **Pluggable Database:** `FREEPDB1`  
> **Schema / Application User:** `dfems_user`  
> **Driver:** Node.js `oracledb` (Thin Mode)

## 2. Relational Tables Catalog (13 Tables)

### Table 1: `APP_USER`
* **Purpose:** Core identity repository for law enforcement officers, forensic examiners, custodians, and compliance auditors.
* **Primary Key:** `User_ID NUMBER GENERATED BY DEFAULT AS IDENTITY`
* **Columns:**
  - `User_ID` (`NUMBER`, PK)
  - `First_Name` (`VARCHAR2(50 CHAR)`, NOT NULL)
  - `Last_Name` (`VARCHAR2(50 CHAR)`, NOT NULL)
  - `Phone_Number` (`VARCHAR2(15 CHAR)`, UNIQUE)
  - `Username` (`VARCHAR2(50 CHAR)`, UNIQUE)
  - `Password_Hash` (`VARCHAR2(255 CHAR)`)
  - `Role` (`VARCHAR2(30 CHAR)`, DEFAULT `'Investigator'`, CHECK)
  - `Account_Status` (`VARCHAR2(20 CHAR)`, DEFAULT `'Active'`, CHECK)
  - `Created_At` (`TIMESTAMP`, DEFAULT `SYSTIMESTAMP`)
* **Constraints:**
  - `chk_user_role`: `CHECK (Role IN ('Admin', 'Investigator', 'Forensic Examiner', 'Evidence Custodian', 'Legal Reviewer', 'Auditor'))`
  - `chk_user_status`: `CHECK (Account_Status IN ('Active', 'Suspended', 'Inactive'))`

### Table 2: `LABORATORY`
* **Purpose:** Accredited digital forensic science laboratories handling technical examination requests.
* **Primary Key:** `Laboratory_ID NUMBER GENERATED BY DEFAULT AS IDENTITY`
* **Columns:**
  - `Laboratory_ID` (`NUMBER`, PK)
  - `Lab_Name` (`VARCHAR2(100 CHAR)`, NOT NULL, UNIQUE)

### Table 3: `INVESTIGATOR`
* **Purpose:** Subtype table capturing law enforcement credentials and badge identifiers.
* **Primary Key:** `User_ID NUMBER`
* **Columns:**
  - `User_ID` (`NUMBER`, PK, FK -> `APP_USER.User_ID` ON DELETE CASCADE)
  - `Badge_Number` (`VARCHAR2(20 CHAR)`, NOT NULL, UNIQUE)

### Table 4: `FORENSIC_ANALYST`
* **Purpose:** Subtype table capturing digital forensic examiner professional certifications and lab affiliation.
* **Primary Key:** `User_ID NUMBER`
* **Columns:**
  - `User_ID` (`NUMBER`, PK, FK -> `APP_USER.User_ID` ON DELETE CASCADE)
  - `Certification` (`VARCHAR2(50 CHAR)`)
  - `Laboratory_ID` (`NUMBER`, NOT NULL, FK -> `LABORATORY.Laboratory_ID`)

### Table 5: `LOCATION`
* **Purpose:** Jurisdictional, incident, and evidence recovery addresses.
* **Primary Key:** `Location_ID NUMBER GENERATED BY DEFAULT AS IDENTITY`
* **Columns:**
  - `Location_ID` (`NUMBER`, PK)
  - `Address` (`VARCHAR2(150 CHAR)`, NOT NULL)

### Table 6: `CASE_TABLE`
* **Purpose:** Criminal investigations, incident files, and case status tracking.
* **Primary Key:** `Case_ID NUMBER GENERATED BY DEFAULT AS IDENTITY`
* **Columns:**
  - `Case_ID` (`NUMBER`, PK)
  - `Title` (`VARCHAR2(100 CHAR)`, NOT NULL)
  - `Status` (`VARCHAR2(20 CHAR)`, DEFAULT `'Open'`, CHECK)
  - `Created_By` (`NUMBER`, NOT NULL, FK -> `APP_USER.User_ID`)
  - `Assigned_To` (`NUMBER`, FK -> `INVESTIGATOR.User_ID`)
  - `Location_ID` (`NUMBER`, FK -> `LOCATION.Location_ID`)
  - `Crime_Type` (`VARCHAR2(100 CHAR)`)
  - `Date_Opened` (`DATE`, DEFAULT `SYSDATE`, NOT NULL)
* **Constraints:**
  - `chk_case_status`: `CHECK (Status IN ('Open', 'Under Investigation', 'Closed', 'Archived'))`

### Table 7: `ASSIGNED`
* **Purpose:** Many-to-many junction table assigning multiple secondary investigators to a case.
* **Composite Primary Key:** `(User_ID, Case_ID)`
* **Columns:**
  - `User_ID` (`NUMBER`, PK, FK -> `INVESTIGATOR.User_ID` ON DELETE CASCADE)
  - `Case_ID` (`NUMBER`, PK, FK -> `CASE_TABLE.Case_ID` ON DELETE CASCADE)
  - `Assigned_Date` (`DATE`, DEFAULT `SYSDATE`)

### Table 8: `EVIDENCE`
* **Purpose:** Core inventory of seized digital and physical forensic evidence items.
* **Primary Key:** `Evidence_ID NUMBER GENERATED BY DEFAULT AS IDENTITY`
* **Columns:**
  - `Evidence_ID` (`NUMBER`, PK)
  - `Description` (`VARCHAR2(255 CHAR)`, NOT NULL)
  - `Collection_Date` (`DATE`, DEFAULT `SYSDATE`, NOT NULL)
  - `Case_ID` (`NUMBER`, NOT NULL, FK -> `CASE_TABLE.Case_ID` ON DELETE CASCADE)
  - `Status` (`VARCHAR2(30 CHAR)`, DEFAULT `'Collected'`, CHECK)
  - `Hash_Value` (`VARCHAR2(64 CHAR)`)
* **Constraints:**
  - `chk_evidence_status`: `CHECK (Status IN ('Collected', 'In Storage', 'Under Analysis', 'Presented in Court', 'Archived', 'Disposed'))`

### Table 9: `DEVICE`
* **Purpose:** Subtype table for physical electronic devices (phones, laptops, thumb drives).
* **Primary Key:** `Device_ID NUMBER GENERATED BY DEFAULT AS IDENTITY`
* **Columns:**
  - `Device_ID` (`NUMBER`, PK)
  - `Serial_Number` (`VARCHAR2(50 CHAR)`, NOT NULL, UNIQUE)
  - `Evidence_ID` (`NUMBER`, NOT NULL, UNIQUE, FK -> `EVIDENCE.Evidence_ID` ON DELETE CASCADE)

### Table 10: `FILE_RECORD`
* **Purpose:** Subtype table for logical forensic artifacts, memory dumps, and disk images. Extended for real disk storage.
* **Primary Key:** `File_ID NUMBER GENERATED BY DEFAULT AS IDENTITY`
* **Columns:**
  - `File_ID` (`NUMBER`, PK)
  - `Evidence_ID` (`NUMBER`, NOT NULL, UNIQUE, FK -> `EVIDENCE.Evidence_ID` ON DELETE CASCADE)
  - `File_Name` (`VARCHAR2(255 CHAR)`)
  - `File_Path` (`VARCHAR2(500 CHAR)`)
  - `File_Size` (`NUMBER`)
  - `Mime_Type` (`VARCHAR2(100 CHAR)`)

### Table 11: `CHAIN_OF_CUSTODY`
* **Purpose:** Append-only cryptographic ledger of transfers, access events, and custodial handoffs.
* **Primary Key:** `Custody_ID NUMBER GENERATED BY DEFAULT AS IDENTITY`
* **Columns:**
  - `Custody_ID` (`NUMBER`, PK)
  - `Timestamp_At` (`TIMESTAMP`, DEFAULT `SYSTIMESTAMP`, NOT NULL)
  - `Action` (`VARCHAR2(255 CHAR)`, NOT NULL)
  - `Evidence_ID` (`NUMBER`, NOT NULL, FK -> `EVIDENCE.Evidence_ID` ON DELETE CASCADE)
  - `User_ID` (`NUMBER`, FK -> `APP_USER.User_ID` ON DELETE SET NULL)

### Table 12: `FORENSIC_ANALYSIS`
* **Purpose:** Detailed findings, technical notes, and evidence extractions recorded by examiners.
* **Primary Key:** `Analysis_ID NUMBER GENERATED BY DEFAULT AS IDENTITY`
* **Columns:**
  - `Analysis_ID` (`NUMBER`, PK)
  - `Findings` (`VARCHAR2(500 CHAR)`, NOT NULL)
  - `Evidence_ID` (`NUMBER`, NOT NULL, FK -> `EVIDENCE.Evidence_ID` ON DELETE CASCADE)
  - `Analyst_ID` (`NUMBER`, NOT NULL, FK -> `FORENSIC_ANALYST.User_ID`)
  - `Timestamp_At` (`TIMESTAMP`, DEFAULT `SYSTIMESTAMP`, NOT NULL)

### Table 13: `AUDIT_LOG`
* **Purpose:** System security, failed login telemetry, and access auditing.
* **Primary Key:** `Log_ID NUMBER GENERATED BY DEFAULT AS IDENTITY`
* **Columns:**
  - `Log_ID` (`NUMBER`, PK)
  - `User_ID` (`NUMBER`, FK -> `APP_USER.User_ID` ON DELETE SET NULL)
  - `Action` (`VARCHAR2(100 CHAR)`, NOT NULL)
  - `Entity_Name` (`VARCHAR2(50 CHAR)`)
  - `Entity_ID` (`NUMBER`)
  - `IP_Address` (`VARCHAR2(50 CHAR)`)
  - `Timestamp_At` (`TIMESTAMP`, DEFAULT `SYSTIMESTAMP`, NOT NULL)
  - `Details` (`VARCHAR2(1000 CHAR)`)

## 3. Database Views (3 Views)

### 1. `v_custody_trail`
```sql
CREATE OR REPLACE VIEW v_custody_trail AS
SELECT
    e.Evidence_ID,
    e.Description AS Evidence_Description,
    c.Title AS Case_Title,
    cc.Custody_ID,
    cc.Timestamp_At,
    cc.Action
FROM CHAIN_OF_CUSTODY cc
JOIN EVIDENCE e ON cc.Evidence_ID = e.Evidence_ID
JOIN CASE_TABLE c ON e.Case_ID = c.Case_ID;
```
* **Rationale:** Provides court-ready, single-query access to the chronological custodial history of any evidence item with full human-readable case context.

### 2. `v_case_summary`
```sql
CREATE OR REPLACE VIEW v_case_summary AS
SELECT
    c.Case_ID,
    c.Title,
    c.Status,
    loc.Address AS Location,
    (u.First_Name || ' ' || u.Last_Name) AS Assigned_Investigator,
    (
        SELECT COUNT(*)
        FROM EVIDENCE e
        WHERE e.Case_ID = c.Case_ID
    ) AS Evidence_Count
FROM CASE_TABLE c
JOIN LOCATION loc ON c.Location_ID = loc.Location_ID
JOIN APP_USER u ON c.Assigned_To = u.User_ID;
```
* **Rationale:** Powers the main case management interface and PDF dossier generation by computing live evidence tallies without application-level N+1 queries.

### 3. `v_evidence_full`
```sql
CREATE OR REPLACE VIEW v_evidence_full AS
SELECT
    e.Evidence_ID,
    e.Description,
    e.Status,
    e.Collection_Date,
    e.Hash_Value,
    c.Title AS Case_Title,
    CASE
        WHEN d.Device_ID IS NOT NULL THEN 'Device'
        WHEN f.File_ID IS NOT NULL THEN 'File'
        ELSE 'Other'
    END AS Evidence_Type,
    d.Serial_Number
FROM EVIDENCE e
JOIN CASE_TABLE c ON e.Case_ID = c.Case_ID
LEFT JOIN DEVICE d ON d.Evidence_ID = e.Evidence_ID
LEFT JOIN FILE_RECORD f ON f.Evidence_ID = e.Evidence_ID;
```
* **Rationale:** Resolves polymorphic evidence inheritance (`DEVICE` vs `FILE_RECORD`) into a unified tabular structure for frontend rendering.

## 4. Stored Procedures & Functions

### Procedure 1: `sp_register_evidence`
* **Signature:** `(p_description VARCHAR2, p_collection_date DATE, p_case_id NUMBER, p_hash_value VARCHAR2, p_new_evidence_id OUT NUMBER)`
* **Logic:** Atomically inserts a new row into `EVIDENCE` using the PL/SQL `RETURNING` clause to obtain the generated ID, then inserts the initial `'Collected at scene'` custody record into `CHAIN_OF_CUSTODY`.
* **Transaction:** Issues `COMMIT;` upon completion.

### Procedure 2: `sp_add_analysis`
* **Signature:** `(p_evidence_id NUMBER, p_analyst_id NUMBER, p_findings VARCHAR2)`
* **Logic:** Updates the status of the evidence item to `'Under Analysis'`, then inserts the findings into `FORENSIC_ANALYSIS`.
* **Transaction:** Issues `COMMIT;` upon completion.

### Procedure 3: `sp_flag_stale_evidence` (PL/SQL Cursor)
* **Signature:** `(p_threshold NUMBER DEFAULT 30, p_cursor OUT SYS_REFCURSOR)`
* **Logic:** Iterates over all non-final status evidence items (`NOT IN ('Archived', 'Disposed', 'Presented in Court')`) using an explicit PL/SQL `CURSOR`. Computes `fn_days_in_current_status(e.Evidence_ID)`. Emits diagnostics via `DBMS_OUTPUT` and opens a `SYS_REFCURSOR` for Node.js API consumption.

### Procedure 4: `sp_transfer_custody` (Transactions, Savepoint, Rollback)
* **Signature:** `(p_evidence_id NUMBER, p_new_status VARCHAR2, p_reason VARCHAR2)`
* **Logic:**
  1. Creates `SAVEPOINT before_transfer;`
  2. Verifies that `Evidence_ID` exists; raises `RAISE_APPLICATION_ERROR(-20003, ...)` if not found.
  3. Updates `EVIDENCE.Status = p_new_status`.
  4. Inserts custody record with action `'Transfer reason: ' || p_reason`.
  5. Commits transaction.
  6. Catches exceptions, executes `ROLLBACK TO before_transfer;`, and re-raises the error.

### Function 1: `fn_days_in_current_status`
* **Signature:** `(p_evidence_id NUMBER) RETURN NUMBER`
* **Logic:** Evaluates the latest `Timestamp_At` in `CHAIN_OF_CUSTODY` where `Action LIKE 'Status changed%'`. If found, computes `TRUNC(SYSDATE) - TRUNC(v_last_change)`. If null, calculates elapsed days from `Collection_Date`.

### Function 2: `fn_verify_hash`
* **Signature:** `(p_evidence_id NUMBER, p_current_hash VARCHAR2) RETURN VARCHAR2`
* **Logic:** Fetches `Hash_Value` from `EVIDENCE`. If hashes match, returns `'MATCH'`. If different, returns `'MISMATCH - POSSIBLE TAMPERING'`. If invalid ID, returns `'ERROR: Evidence not found'`.

## 5. Database Triggers (3 Triggers)

| Trigger Name | Timing & Event | Target Table | Business Rule Enforced |
|---|---|---|---|
| `trg_evidence_status_change` | `AFTER UPDATE OF Status` | `EVIDENCE` | Automatically writes `'Status changed: OLD -> NEW'` into `CHAIN_OF_CUSTODY`. |
| `trg_custody_no_update` | `BEFORE UPDATE` | `CHAIN_OF_CUSTODY` | Raises `ORA-20001`. Enforces absolute append-only immutability. |
| `trg_custody_no_delete` | `BEFORE DELETE` | `CHAIN_OF_CUSTODY` | Raises `ORA-20002`. Prevents unauthorized log destruction. |

## 7. Dialect Differences: DA2 MySQL vs Oracle 26ai Free

| MySQL Syntax (DA2 Screenshots) | Oracle 26ai Free Syntax |
|---|---|
| `INT AUTO_INCREMENT PRIMARY KEY` | `NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` |
| `VARCHAR(255)` | `VARCHAR2(255 CHAR)` |
| `CURRENT_TIMESTAMP` | `SYSTIMESTAMP` |
| `LAST_INSERT_ID()` | `INSERT ... RETURNING Column INTO :var` |
| `LIMIT 5` | `FETCH FIRST 5 ROWS ONLY` |
| `SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = '...'` | `RAISE_APPLICATION_ERROR(-20001, '...')` |
| `DATEDIFF(CURRENT_DATE, v_date)` | `TRUNC(SYSDATE) - TRUNC(v_date)` |
| `DELIMITER $$ ... END$$` | Standard `/` block terminators in PL/SQL |

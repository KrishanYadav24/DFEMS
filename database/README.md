# DFEMS — ORACLE DATABASE 26ai LAYER GUIDE

> **System:** Digital Forensic Evidence Management System (DFEMS)  
> **Database:** Oracle AI Database 26ai Free  
> **Pluggable Database (PDB):** `FREEPDB1`  
> **Application User:** `dfems_user`  
> **Default Port:** `1521`  
> **Driver:** Node.js `oracledb` (Thin Mode)  

---

## 1. Overview

This directory contains the complete database scripts and technical documentation for the DFEMS Oracle Database 26ai layer. It translates and integrates the requirements from **DA1**, **DA2**, and **`MASTER_PROJECT_SPEC.md`** into native, high-performance Oracle SQL and PL/SQL.

### File Manifest

| File | Purpose | Execution Mode |
|---|---|---|
| **`oracle_schema.sql`** | Clean Empty-Schema DDL (13 tables, primary/foreign/check/unique constraints, 12 indexes). Contains **zero seed records**. | SQL*Plus / Database Client |
| **`oracle_programs.sql`** | Procedural logic (3 Views, 2 Functions, 4 Stored Procedures including Cursor & Transaction Savepoints, 3 Triggers). | SQL*Plus / Database Client |
| **`seed_demo_data.sql`** | Optional academic evaluation dataset from DA2 (10 users, 8 cases, 15 evidence, 33 custody events, etc.) with sequence advancement. | SQL*Plus / Evaluation Only |
| **`oracle_schema_with_seeds.sql.bak`** | Preserved exact backup of original integrated DDL + seed dataset script. | Backup Archive |
| **`demo_queries.sql`** | Executable test suite (CRUD, Joins A1–A4, Nested Queries B1–B4, Aggregates C1–C4, Procedure tests, Trigger tests, Transaction tests). | SQL*Plus / Demo Console |
| **`DBMS_OBJECTS.md`** | Comprehensive architectural object catalog detailing tables, columns, indexes, signatures, and queries. | Documentation |
| **`README.md`** | Setup instructions, prerequisite verification, execution order, and troubleshooting. | Documentation |

## 2. Prerequisites & Safety Constraints

1. **Oracle AI Database 26ai Free** must be running locally with the listener active on port `1521`.
2. The Pluggable Database **`FREEPDB1`** must be open in `READ WRITE` mode.
3. The dedicated schema user **`dfems_user`** must exist and have the following privileges:
   ```sql
   -- Granted by SYSDBA:
   GRANT CONNECT, RESOURCE, CREATE VIEW, CREATE PROCEDURE, CREATE TRIGGER TO dfems_user;
   ALTER USER dfems_user QUOTA UNLIMITED ON USERS;
   ```
4. **Safety Rule:** No scripts contain hardcoded credentials or destructive `DROP` statements. Passwords must never be printed, passed on the command line in plaintext, or committed to source control. Always rely on SQL*Plus password prompts or environment variables stored in gitignored `.env` files.

## 3. Recommended Script Execution Sequence

When ready to initialize the database schema, execute the scripts in the following order using SQL*Plus or Oracle SQL Developer:

### Step 1: Connect to Pluggable Database as `dfems_user`
Prompt interactively for password without exposing credentials on the terminal:
```bash
sqlplus dfems_user@//localhost:1521/FREEPDB1
```

### Step 2: Create Empty Schema Tables & Indexes
```sql
@database/oracle_schema.sql
```
* **What it does:** Creates all 13 tables (`APP_USER`, `LABORATORY`, `INVESTIGATOR`, `FORENSIC_ANALYST`, `LOCATION`, `CASE_TABLE`, `ASSIGNED`, `EVIDENCE`, `DEVICE`, `FILE_RECORD`, `CHAIN_OF_CUSTODY`, `FORENSIC_ANALYSIS`, `AUDIT_LOG`) and applies the 12 performance/integrity indexes. Zero rows are inserted.

### Step 3: Compile Views, Procedures, Functions & Triggers
```sql
@database/oracle_programs.sql
```
* **What it does:** Compiles views (`v_custody_trail`, `v_case_summary`, `v_evidence_full`), functions (`fn_days_in_current_status`, `fn_verify_hash`), procedures (`sp_register_evidence`, `sp_add_analysis`, `sp_flag_stale_evidence`, `sp_transfer_custody`), and append-only triggers.

### Step 4: Secure Initial Administrator Setup (Production Mode)
From the project root or `backend/` directory, run the interactive administrative bootstrap CLI:
```bash
node backend/scripts/bootstrapAdmin.js
```
* **What it does:** Securely prompts for administrator credentials, enforces complexity policies, hashes the password via bcrypt (work factor 12), creates the initial `Admin` user record, and logs an immutable initialization audit event.

---

### Alternative: Academic Demo Dataset (For DA2 Evaluation Only)
If you wish to populate the academic demonstration dataset after Step 3:
```sql
@database/seed_demo_data.sql
```
* **What it does:** Populates all 110 records from the DA2 specification and restarts the `GENERATED BY DEFAULT AS IDENTITY` sequences so subsequent application inserts do not cause primary key conflicts.
* **To run the test query suite against the demo data:**
```sql
@database/demo_queries.sql
```

## 5. Node.js `oracledb` Integration Details

The Node.js backend connects using **`oracledb` in Thin Mode**:

```javascript
import oracledb from 'oracledb';

const pool = await oracledb.createPool({
  user: process.env.DB_USER,
  password: process.env.DB_PASSWORD,
  connectString: process.env.DB_CONNECT_STRING || 'localhost:1521/FREEPDB1',
  poolMin: 2,
  poolMax: 10,
  poolIncrement: 2
});
```

* **Thin Mode Benefits:** 100% pure JavaScript protocol. No Oracle Instant Client C-binaries required.
* **SYS_REFCURSOR Support:** Procedure `sp_flag_stale_evidence` returns an open cursor directly fetched by Node.js.
* **Bind Variables:** Standard named binds (`:caseId`, `:hashValue`) prevent SQL injection attacks.

## 6. Development Seed Accounts & Secure Initial Administrator Setup

### 6.1 Policy on Seed Accounts & Passwords
1. **No Hardcoded Default Passwords:** No production or permanent user account shall ever have a default or hardcoded password.
2. **Empty Schema by Default:** The primary schema initialization script `oracle_schema.sql` deploys clean empty tables.
3. **Password Security:** All credentials in `APP_USER` must be stored as salted bcrypt hashes (work factor >= 12). Plaintext passwords are never logged, stored, or printed.

### 6.3 Secure Initial Administrator Bootstrapping Process (Production Mode)
For secure deployment without pre-seeded accounts:
1. Run `oracle_schema.sql` and `oracle_programs.sql` to establish empty tables, views, procedures, and triggers.
2. Execute the administrative provisioning script:
   ```bash
   node backend/scripts/bootstrapAdmin.js
   ```
3. The script:
   - Connects to `FREEPDB1` using the database credentials in the gitignored `.env` file.
   - Prompts interactively for the administrator's username, full name, phone number, and password.
   - Enforces a strong password policy (minimum 12 characters, uppercase, lowercase, numbers, and symbols).
   - Masks the entered password on the terminal (`*`).
   - Generates a salted bcrypt hash with work factor `12`.
   - Inserts a single record into `APP_USER` with `Role = 'Admin'` and `Account_Status = 'Active'`.
   - Emits an initial audit record into `AUDIT_LOG` recording the initialization event with timestamp and host IP.
